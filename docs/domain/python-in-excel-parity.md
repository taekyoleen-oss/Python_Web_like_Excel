# Python in Excel 대응 상세

마스터 표: 설계서 §1.4 (`docs/pygrid-studio-design.md`). 이 문서는 **구현 중 Excel과 다르게 동작하기로 결정한 항목**을 누적 기록한다.

| # | 항목 | Excel 동작 | PyGrid 동작 | 근거 | 결정일 |
|---|------|-----------|------------|------|--------|
| 1 | 계산 순서 | 뒤쪽 셀 참조 시 이전 값 사용 | `xl()` 의존성을 따라 선행 블록 먼저 실행 | 초보자 직관(참조는 항상 최신 값). 인터뷰 확정 | 2026-09-02 |
| 2 | 코드 위치 | 셀 안 `=PY()` | 우측 Python 패널의 블록 | Python Editor 창과 동일 구조. 설계서 §1.1 | 2026-09-02 |
| 3 | Excel 수식 혼용 | 가능 | v1 미지원(계산은 전부 Python) | 설계서 §1.4 | 2026-09-02 |
| 4 | `xl` 별칭 호출(`f = xl; f("A1")`) | 의존성 추적 불가(동일 한계) | 동일 — ast 분석 누락, 런타임 RuntimeError 안전망 | conversion-rules #14 | 2026-09-03 |
| 5 | XLSX 내보내기의 날짜 | 날짜 셀(서식 포함) | ISO 문자열(값만 정책) — 다시 열면 문자열 | v1 값만 내보내기 트레이드오프. 서식 기록은 v2 | 2026-09-03 |
| 6 | 행/열 삽입 시 `xl()` 참조 | 수식처럼 자동 조정 | v1 미조정 — 코드 문자열 리터럴 유지 | 참조 재작성은 블록 앵커 재배치와 함께 v2 | 2026-09-03 |
| 7 | 결과 위치 변경 | 셀을 잘라내기/붙여넣기하면 `=PY()` 수식이 따라 이동 | 카드의 **출력 위치 지정** → 그리드 클릭으로 앵커 재지정(이전 spill 제거 후 재실행, 한 undo 단계). 코드 안 `xl()` 참조는 여전히 재작성하지 않는다(#6) | 셀 수식이 없어 잘라내기 이동이 불가능 — 명시적 재지정으로 대체 | 2026-09-04 |
| 8 | 출력 선택 | `=PY()`는 마지막 표현식만 반환(다른 값은 코드를 고쳐야 함) | 블록별 **출력**(변수 선택·열 선택·상위 N행)을 코드 수정 없이 지정 | 초보자가 `df.head(3)[["a"]]`를 쓰지 않고도 원하는 부분만 펼치도록. 필터는 §3.3 변환 **전에** 적용 | 2026-09-04 |
| 9 | 문서(마크다운) 블록 | 없음(설명은 셀 텍스트로) | `kind: "markdown"` 블록 — 실행·spill 없음, 앵커는 위치/목차 대상일 뿐 셀에 아무것도 쓰지 않는다. 그리드 앵커에는 `§` 배지(파란색 아님 — Python 관여 아님) | 노트북형 문서화 + 목차. 렌더러는 원시 HTML을 해석하지 않아 공유 파일이 안전하다 | 2026-09-04 |

새 항목은 구현 중 발견 즉시 추가한다.
